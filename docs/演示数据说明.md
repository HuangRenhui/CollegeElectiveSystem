# 演示数据说明

> 本文档说明项目内置的演示数据：包含什么、如何使用、以及各页面能看到的效果。
>
> 演示数据用于**功能演示、验收测试与二次开发**，让系统初始状态即具备完整业务内容，
> 无需人工逐条录入。

---

## 1. 快速使用

### 方式一：一键初始化（建表 + 基础数据 + 演示数据）

```bash
cd CollegeElectiveSystem

# 脚本会自动切换目标库，无需手工指定
mysql -uroot -p < scripts/init-db.sql
```

### 方式二：仅补充演示数据（表结构与基础数据已就绪）

```bash
mysql -uroot -p <目标库> < scripts/init-demo-data.sql
```

### 方式三：Docker 环境

```bash
# 容器启动后执行（容器首次启动已自动完成建表与基础数据）
docker exec -i elective-mysql mysql -uroot -proot123456 college_elective \
  < backend/src/main/resources/db/demo-data.sql
```

### 方式四：仅补「当前学期」的成绩与教学评价增量（可重复执行）

```bash
mysql -uroot -p college_elective < scripts/seed-extra-demo.sql
```

该脚本解决一个容易踩的坑：**学生 / 教师 / 管理员三个「教学评价」页面默认只筛当前学期**，
而 `demo-data.sql` 的评价全部挂在历史学期，导致默认视图为空；
另外教师 6/7/8 原本在当前学期没有任何课程。脚本会为当前学期补上

- 教师 6/7/8 的当前学期课程（含排课）
- 每门课 13~14 名「已修完」学生（`status = 2`）及其成绩、评价
- 若干条公告（1 条草稿、1 条已下架，便于演示状态筛选）与评价/成绩相关操作日志

脚本**幂等**（全部 `INSERT ... WHERE NOT EXISTS` 守卫，重复执行不会产生重复数据），
且**不修改 `course.selected_count`**，因此不影响选课余量与 Redis 缓存。

> **提示**：`scripts/init-db.sql` 末尾已通过 `SOURCE seed-extra-demo.sql;` 引入本脚本，
> 因此**重跑一键初始化不会漏掉这批数据**。
>
> 开发环境下应用启动时会**自动创建缺失的表结构**，
> 因此实际只需导入 `data.sql`、`demo-data.sql` 与 `seed-extra-demo.sql` 三个数据脚本。

## 3. 数据设计说明

### 3.1 学期分布

| 学期 | 编码 | 状态 | 用途 |
| --- | --- | --- | --- |
| 第一学期 | `2025-2026-1` | 已结束 | 提供历史成绩数据（用于成绩单） |
| 第二学期 | `2025-2026-2` | 已结束 | 提供历史成绩数据 |
| **当前学期** | `2026-2027-1` | **选课中** | 选课、课表的主数据来源 |

### 3.2 选课记录构成

```
 44 条  当前学期已选课（status=1）  → 选课中心、我的课表、学生名单
181 条  当前学期已修完（status=2）  → 我的成绩、教学评价（当前学期默认视图）
 35 条  历史学期已修完（status=2）  → 成绩单、绩点统计
  1 条  已退选（status=0）          → 演示退选状态
```

> 说明：选课中心与课表只展示 `status = 1` 的记录，因此当前学期那 181 条
> 是挂在 13 门课上的**演示用「已完成」记录**（每门课 13~14 人），
> 目的是让评价明细、成绩录入单这类列表有合理的长度，不至于只有两三条。

### 3.3 成绩数据构成

| 学期 | 已发布（status=1） | 草稿（status=0） | 用途 |
| --- | ---: | ---: | --- |
| 当前学期 | 162 | 18 | 学生成绩单、教师端「待发布」场景 |
| 历史学期 | 35 | 0 | 成绩单与绩点统计 |
| **合计** | **197** | **18** | |

草稿成绩集中在 3 门课（人工智能导论 5 条、学术英语写作 4 条、体育与健康 9 条），
用于演示教师端「录入 → 发布 / 撤回」的不同状态。

**成绩覆盖分数段**（让统计图表有形状）：

| 分数段 | 说明 |
| --- | --- |
| 90 分以上 | 绩点 4.0 |
| 80-89 分 | 绩点 3.7 |
| 70-79 分 | 绩点 2.7 |
| 60-69 分 | 绩点 1.0-1.5 |
| 60 分以下 | 不及格（含重修标记） |

### 3.4 评价数据构成

159 条评价全部挂载在 **`status = 2`（已修完）** 的选课记录上，
满足「仅可评价已修完课程」的参评资格校验。

| 状态 | 数量 | 用途 |
| --- | ---: | --- |
| 已公开（status=2） | 157 | 教师端可见，计入课程平均分 |
| 已提交（status=1） | 1 | 管理员端「已提交」筛选、待审核场景 |
| 已隐藏（status=3） | 1 | 管理员下架违例演示，**不计入**平均分 |

按学期分布：

| 学期 | 评价数 | 说明 |
| --- | ---: | --- |
| **当前学期** | **136** | 覆盖 13 门课、**8 位教师**；每门课 8~11 条，参评率 57%~79% |
| 历史学期 | 23 | 覆盖 7 门课、4 位教师（见下表） |

> ⚠️ **当前学期这 136 条为什么必须有**：三个评价页面（学生 / 教师 / 管理员）
> 默认只筛**当前学期**，历史学期的评价在默认视图里看不到。
> 少了这批数据，评价相关页面打开就是空的。

**历史学期覆盖情况**（7 门课程、4 位教师）：

| 课程 | 授课教师 | 评价数 | 平均分区间 |
| --- | --- | ---: | --- |
| 面向对象程序设计 | 张明远 | 5 | 3.9 - 4.9 |
| 数据库原理与应用 | 张明远 | 4 | 3.4 - 4.9 |
| 高等数学（上） | 林知远 | 3 | 3.5 - 4.3 |
| 大学英语（一） | 陈静怡 | 3 | 4.3 - 5.0 |
| 计算机网络 | 张明远 | 3 | 3.8 - 4.8 |
| 操作系统 | 林知远 | 2 | 3.9 - 4.3 |
| 线性代数 | 林知远 | 3 | 1.0(已隐藏) / 3.8 / 4.3 |

> 各课程平均分刻意拉开梯度，便于验证评价汇总卡片、管理员统计卡片与
> 「评分档位」筛选（高 / 良好 / 一般 / 偏低）。
>
> **待评价**：全库共 **57 条**「已修完但未评价」的选课记录，分散在全部 20 名学生上
> （每人 1~14 条），因此用任意学生账号登录都能在「待评价」页看到内容。

### 3.5 数据自洽性保障

脚本末尾通过 SQL 自动重算，确保数据一致：

```sql
-- 课程已选人数 = 该课程 status=1 的选课记录数
UPDATE course c SET c.selected_count = (...);

-- 学生已获学分 = 已修完且及格课程的学分之和
UPDATE student s SET s.total_credit = (...);
```

**时间冲突校验**：全部 44 条当前学期选课组合均通过四维冲突检测（同天 + 节次 + 周次 + 单双周），
无任何冲突，与系统的选课校验逻辑保持一致。

**评价数据校验**：

- 159 条评价的 `selection_id` 均取自 `status = 2`（已修完）的选课记录，
  否则会违反后端「仅可评价已修完课程」的参评资格校验；
- `teacher_id` 与课程表的授课教师一致，保证教师端汇总不串课；
- `average_score` 为四维评分的算术平均（保留 1 位小数），与后端计算口径完全一致。

### 3.6 可重复执行

脚本开头会清理本系统的业务数据后重建：

```sql
DELETE FROM course_review;
DELETE FROM course_grade;
DELETE FROM course_selection;
DELETE FROM sys_log;
UPDATE course SET selected_count = 0;
```

- 仅清理这 4 张表，**不影响** `data.sql` 中的院系、专业、用户、课程等基础数据；
- 其余表使用 `ON DUPLICATE KEY UPDATE`，重复执行不会产生重复记录；
- 若部署在其他业务库中，**不会影响该库的既有数据**。

## 6. 验证数据是否导入成功

```sql
SELECT '院系' AS 数据表, COUNT(*) AS 记录数 FROM department
UNION ALL SELECT '专业', COUNT(*) FROM major
UNION ALL SELECT '用户', COUNT(*) FROM sys_user
UNION ALL SELECT '学生', COUNT(*) FROM student
UNION ALL SELECT '教师', COUNT(*) FROM teacher
UNION ALL SELECT '课程', COUNT(*) FROM course
UNION ALL SELECT '选课记录', COUNT(*) FROM course_selection
UNION ALL SELECT '成绩记录', COUNT(*) FROM course_grade
UNION ALL SELECT '课程评价', COUNT(*) FROM course_review
UNION ALL SELECT '操作日志', COUNT(*) FROM sys_log;
```

**预期结果**：5 / 9 / 29 / 20 / 8 / 20 / 261 / 215 / 159 / 37+
（最后一个「操作日志」会随应用使用持续增长，≥ 37 即视为正常）

## 7. 清空演示数据

如需恢复为空白状态（保留表结构与基础数据）：

```sql
DELETE FROM course_review;
DELETE FROM course_grade;
DELETE FROM course_selection;
DELETE FROM sys_log;
UPDATE course SET selected_count = 0;
UPDATE student SET total_credit = 0.0;
```

若需恢复到仅含 `data.sql` 的状态，重新执行 `data.sql` 即可。
