## [未发布] - 2026-10-10

### 新增

**教务代选（管理员）**

- 新增 `CourseSelectionService` 的 3 个方法：
  `pageStudentSelections`（查询指定学生的选课记录）、
  `adminAddSelection`（教务代选）、`adminRemoveSelection`（教务代退选）；
- `AdminStudentController` 新增对应 3 个端点
  （`GET/POST /admin/students/{studentId}/selections`、
  `DELETE /admin/students/{studentId}/selections/{courseId}`），与前端 `api/admin.js` 对齐；
- **校验项设计**：代选**仅跳过**「选课开关」与「学期状态 + 时间窗口」两项窗口类约束，
  其余（课程状态、学分上限、时间冲突、容量、重复选课）全部保留；
- **学期基准**：`semesterId` 从课程反查而非取「当前学期」，
  避免代选发生在选课期之外时校验与落库错位；
- **权限校验**：`requireAdmin()` 内聚在 Service 层再校验一次角色，
  不依赖 Controller 的 `@PreAuthorize`（Service 可能被其它入口复用）；
- **审计追溯**：`reason` 为必填（不少于 2 个字符），
  经 `@OperationLog(saveParam = true)` 写入 `sys_log.request_param`，
  **无需在 `course_selection` 表额外增加字段**。

### 修复

- 修复 `adminRemoveSelection` 中 `lambdaQuery(` 缺少右括号的语法错误；
- 修复 `adminRemoveSelection` 查询条件误将 `semesterId` 传给 `getStudentId` 的参数错误；
- 统一 `adminRemoveSelection` 接口与实现的方法签名（3 参数，返回 `SelectionResultVO`）；
- `persistSelection` 中的魔法值 `1` 改用常量 `SELECT_TYPE_NORMAL`，
  并在复用历史记录时重置 `selectType`，保证「学生复选代选过的课程」后来源可正确还原。

### 新增

**选课模块收尾**——`CourseSelectionService` 接口声明的 8 个方法**全部实现**

- `dropCourse` —— 学生退课：课程可退选校验、已录成绩拦截、归还 Redis 余量、
  记录置为已退选（软删除）、同步数据库计数；两处写库处于同一事务
- `syncSelectionCount` —— 一致性兜底：三方比对
  （数据库计数 / Redis 容量 / Redis 已选集合基数）后按需修复
- `returnReservation` —— 退课与选课回滚共用的 Redis 预占归还方法

### 变更

- **`SelectionSyncTask.TASK_ENABLED` 置为 `true`**：定时兜底任务默认启用，每 5 分钟执行一次
- **`syncSelectionCount` 改为三方比对**：原先只比对数据库计数，
  导致「数据库没问题、Redis 余量被写错」的场景被直接跳过，
  无法满足验收清单中「手工制造数据偏差后能校正」的要求
- **`syncSelectionCount` 同时重建「已选学生集合」**：集合是 Lua 中 `SISMEMBER`
  判重的唯一依据（残留已退课学生会造成重新选课误判为 3003），
  必须与容量 key 同源、同 TTL 一并写回
- **数据库侧改为一次批量查询**：用 `selectValidSelectionsByCourseIds` 一次取出
  全部课程的选课记录并按课程分组，替代逐门 `selectCount`（N 次查询 → 1 次），
  分组结果同时就是重建集合所需的成员列表
- **退课状态语义细化**：`status = 0`（已退选）按「尚未选择该课程」返回 3004；
  `status = 2`（已修完）按「不允许退课」返回 3009

## [未发布] - 2026-09-27

### 新增

**选课模块核心流程**（`CourseSelectionServiceImpl`）

- `selectCourse` —— 学生选课主流程：选课开关与时间窗口校验、课程状态校验、学分上限校验、
  时间冲突检测、缓存回源、`select_course.lua` 原子预占、落库、数据库计数同步；
  任一步失败均归还 Redis 预占
- `prepareCourseCache` —— 缓存回源（原规划名 `ensureCacheReady`）：
  `SETNX` 短锁 + 双重检查防止并发回源互相覆盖，未抢到锁时自旋等待（5 × 50ms）
  后重新探测，避免首次开放选课时大量「缓存未就绪（3010）」失败
- 配套私有方法 `awaitCacheReady`、`normalizeLuaResult`、`rollbackReservation`

### 变更

- **摘除 `CourseSelectionServiceImpl` 的 `PendingImplementation` 标记**：
  Controller 可直接调用已实现方法；未实现的 `dropCourse`、`syncSelectionCount`
  改为 `throw PendingFeature.unsupported(...)`，返回业务码 `5006` 而非 HTTP 500
- **摘除 `CourseGradeServiceImpl` 的 `PendingImplementation` 标记**：
  成绩模块的 3 个查询方法（`pageGrades`、`listCourseGradeSheet`、
  `getStudentGradeReport`）此前被 Bean 层标记一律拦截为 5006，摘除后立即可用；
  未实现的 `inputGrades`、`publishGrades`、`revokeGrades` 同样改抛
  `PendingFeature.unsupported(...)`。至此代码库中已无类实现该标记
- **统一学期基准**：学分统计与时间冲突检测一律以「课程所属学期」为准；
  冲突检测抽分为「对外预检取当前学期」与「内部私有方法按传入学期」两层
- **冲突检测复用**：`checkConflict` 与 `selectCourse` 共用 `findConflicts`，
  避免两处各自实现导致行为不一致

### 修复

- 移除 `CourseSelectionMapper#sumCreditByStudentId`：该方法与既有的 `sumSelectedCredit`
  功能重复，且**缺少对应的 XML 映射**，调用时会抛
  `BindingException: Invalid bound statement (not found)`；
  `checkCreditLimit` 已改回使用 `sumSelectedCredit`
- 修正 `selectCourse` 中 `result == null` 恒真/恒假的死代码分支
- 合并两个完全重复的回滚方法（`rollbackReservation` / `rollbackSelection`）
- 修正格式化与命名问题（`if(` → `if (`、`studentsIds` → `studentIds`、
  `catch (RuntimeException | Error e)` → `catch (RuntimeException e)` 等）

- 统一响应结构 `Result` / `PageResult` 与全局异常处理器
- Knife4j OpenAPI 3 接口文档

**认证与安全**

- JWT 令牌签发、验签与 Redis 白名单机制
- Spring Security 无状态认证，URL 级与方法级权限控制
- 登录失败计数与临时锁定（连续 5 次锁定 15 分钟）
- 令牌滑动续期（剩余有效期不足阈值自动续期）
- 密码 bcrypt 加密，修改密码后强制重新登录
- 401 / 403 统一 JSON 响应处理器

**数据模型**

- 13 张业务表设计与 DDL 脚本（`schema.sql`）；`course_review` 于 [未发布] 版本补充
- 完整初始化数据（`data.sql`）：5 院系、9 专业、11 用户、10 课程、6 教室、3 学期、3 公告
- 逻辑删除、乐观锁（`course.version`）、自动填充创建/更新时间

**核心业务**

- **选课**：Redis Lua 脚本原子预占（查重 + 余量校验 + 扣减 + 记录），有效防止超选与重复选课
- **退课**：Lua 脚本原子归还余量，支持成绩录入后禁止退课
- **时间冲突检测**：基于星期 + 节次 + 周次 + 单双周四维判定，支持选课预检与排课校验
- **学分上限控制**：按学期限制可选总学分
- **缓存预热与同步**：一键预热课程缓存，定时任务每 5 分钟校正数据一致性
- **课程管理**：课程 CRUD、排课管理、状态变更、容量校验
- **成绩管理**：批量录入草稿、发布、撤回；总评计算（平时 30% + 期末 70%）与 4.0 制绩点换算
- **课表查询**：学生课表与教师课表
- **教务管理**：院系、专业、教室、学期、公告的全流程维护
- **学生/教师管理**：账号自动创建、信息维护、启用禁用
- **数据统计**：学生/教师/课程/选课数量统计，热门课程排行，院系分布与成绩分布图表

**基础设施**

- 操作日志注解 `@OperationLog` + AOP 异步落库（记录操作人、耗时、参数、异常）
- 请求耗时拦截器与慢接口告警日志
- 异步线程池配置（拒绝策略为 CallerRunsPolicy，保证日志不丢失）
- Redis 序列化配置（String Key + JSON Value，支持 LocalDateTime）
- Jackson 全局配置（时间格式化、Long 转 String 防精度丢失）
- 选课开关（Redis 动态切换，管理员可随时关闭选课通道）

**前端功能**

- 登录页（含角色演示账号一键填充）
- 首页仪表盘（按角色展示差异化统计与快捷操作）
- 学生端：选课中心（卡片式浏览 + 余量进度条）、我的选课、我的课表（网格课表视图）、我的成绩（成绩单 + 绩点统计）
- 教师端：工作台（授课卡片）、成绩录入（批量填充 + 发布/撤回）、学生名单、教学课表
- 管理端：数据概览（ECharts 图表）、课程管理（含排课编辑）、学生管理、教师管理、基础信息（院系/专业/教室）、学期管理、公告管理、操作日志
- 路由权限守卫（登录校验 + 角色校验）
- 顶栏公告通知、学期标签、个人中心、修改密码

**部署**

## 版本号说明

| 版本号变更 | 含义 |
| --- | --- |
| 主版本号（1.x.x → 2.x.x） | 不兼容的重大变更 |
| 次版本号（1.0.x → 1.1.x） | 向后兼容的功能新增 |
| 修订号（1.0.0 → 1.0.1） | 向后兼容的问题修复 |

## 变更类型

| 类型 | 说明 |
| --- | --- |

| 变更 Changed | 对现有功能的变更 |
| 弃用 Deprecated | 即将移除的功能 |
| 移除 Removed | 已移除的功能 |
