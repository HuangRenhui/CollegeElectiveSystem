`SecurityConfig.WHITE_LIST` 缺少微信的三个接口，而它们**全部发生在

| 接口 | 调用时机 | 缺失白名单的后果 |

| `/wx/bind` | 首次绑定系统账号 | 401 → **无法完成绑定** |

接口自身逻辑完全正确，问题只在白名单，因此**编译、单元测试、静态检查

（实测返回 `401 未登录或登录已过期`）。

修复：三者加入 `WHITE_LIST`。**不可**写成 `/wx/**`，因为
`/wx/subscribe` 系列依赖 `SecurityUtils.getUserId()`，必须保持鉴权。

### ⚠️ 数据库变更说明（升级已有环境时必读）

本次新增 `message_notice` 表，并**要求 `semester` 表已有
`review_start_time` / `review_end_time` 两列**。两者的生效方式**不同**：

| 变更 | 开发环境（非 prod） | 生产环境 |
| --- | --- | --- |
| 新增 `message_notice` 表 | ✅ 启动时**自动创建** | ❌ 需手工建表 |
| `semester` 新增两列 | ⚠️ **不会自动添加**，须手工 `ALTER` | ❌ 须手工 `ALTER` |

原因：`config/DatabaseInitializer` 只执行 `CREATE TABLE IF NOT EXISTS`
（且会过滤 `DROP TABLE`），**不做 `ALTER TABLE` 加列**。
「已存在的表」不会被修改，因此缺列的旧表不会被自动修复
——这正是此前 `Unknown column 'review_start_time'` 报错的根因。

补齐列（已有环境执行一次即可）：

```sql
ALTER TABLE `semester`
    ADD COLUMN `review_start_time` DATETIME NULL COMMENT '评价开放开始时间（NULL 表示不限制）'
        AFTER `select_end_time`,
    ADD COLUMN `review_end_time`   DATETIME NULL COMMENT '评价开放结束时间（NULL 表示不限制）'
        AFTER `review_start_time`;
```
