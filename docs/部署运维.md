## 2. 开发环境搭建

### 2.1 数据库初始化

```bash
# 建库建表（含全部 14 张业务表）
mysql -h localhost -u root -p < backend/src/main/resources/db/schema.sql

# 导入基础数据（院系、专业、用户、课程、教室、学期、公告）
mysql -h localhost -u root -p college_elective < backend/src/main/resources/db/data.sql

# 导入演示数据（选课记录、成绩、课程评价、操作日志，可选但推荐）
mysql -h localhost -u root -p college_elective < backend/src/main/resources/db/demo-data.sql

# 验证
mysql -h localhost -u root -p -e "USE college_elective; SHOW TABLES;"
```

预期输出 **14 张**业务表（`course_review` 为课程评价表）。

> **提示**：开发环境下应用启动时会自动创建缺失的表，
> 因此也可只执行两个数据脚本（`data.sql` + `demo-data.sql`），
> 详见 [演示数据说明](./演示数据说明.md)。
> 一键初始化推荐直接用 `scripts/init-db.sql`。

### 2.2 启动 Redis

```bash
# 无密码（开发环境默认）
redis-server

# 带密码
redis-server --requirepass redis123456

# 验证连通性
redis-cli ping        # 期望输出 PONG
redis-cli -a redis123456 ping
```

### 2.3 配置后端

编辑 `backend/src/main/resources/application-dev.yml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/college_elective?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
    username: root
    password: 你的数据库密码
  data:
    redis:
      host: localhost
      port: 6379
      password:      # Redis 有密码时填写
      database: 0
```

### 2.4 启动后端

```bash
cd backend

# 编译
mvn clean compile

# 运行（开发模式）
mvn spring-boot:run

# 或指定端口运行
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8081"
```

启动成功标志：

```
----------------------------------------------------------
高校选修课管理系统启动成功！
本地地址:   http://localhost:8080/api
接口文档:   http://localhost:8080/api/doc.html
当前环境:   dev
----------------------------------------------------------
```

### 2.5 启动前端

```bash
cd frontend

# 安装依赖（首次）
npm install

# 使用国内镜像加速
npm config set registry https://registry.npmmirror.com

# 启动开发服务器
npm run dev
```

访问 http://localhost:5174

## 3. 配置说明

### 3.1 后端配置项

`application.yml` 中的自定义配置：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `elective.jwt.secret` | 内置默认值 | JWT 签名密钥，**生产必须覆盖**，长度 ≥ 32 字节 |
| `elective.jwt.expire-seconds` | 7200 | 令牌有效期（秒） |
| `elective.jwt.refresh-threshold-seconds` | 600 | 自动续期阈值（秒） |
| `elective.jwt.header` | Authorization | 令牌请求头名 |
| `elective.jwt.prefix` | `Bearer ` | 令牌前缀 |
| `elective.selection.max-credit` | 30 | 单学生学期学分上限 |
| `elective.selection.lock-wait-millis` | 300 | 选课锁等待（毫秒） |
| `elective.selection.enabled` | true | 是否开放选课 |
| `elective.cors.allowed-origins` | localhost 相关 | 允许的跨域来源 |

### 3.2 多环境配置

| 文件 | 用途 | 关键差异 |
| --- | --- | --- |
| `application.yml` | 公共配置 | 端口、MyBatis-Plus、日志、自定义配置 |
| `application-dev.yml` | 开发环境 | 本地数据库、SQL 日志打印、文档开放 |
| `application-prod.yml` | 生产环境 | 环境变量注入、连接池扩大、日志落盘、文档关闭 |

### 3.3 环境变量（生产必需）

| 变量 | 说明 | 示例 |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | 激活的配置 | `prod` |
| `SPRING_DATASOURCE_URL` | 数据库连接串 | `jdbc:mysql://mysql:3306/college_elective?...` |
| `SPRING_DATASOURCE_USERNAME` | 数据库账号 | `root` |
| `SPRING_DATASOURCE_PASSWORD` | 数据库密码 | `强密码` |
| `SPRING_DATA_REDIS_HOST` | Redis 主机 | `redis` |
| `SPRING_DATA_REDIS_PORT` | Redis 端口 | `6379` |
| `SPRING_DATA_REDIS_PASSWORD` | Redis 密码 | `强密码` |
| `JWT_SECRET` | JWT 密钥 | 至少 32 位随机字符串 |

## 4. Docker 部署

### 4.1 一键启动

```bash
# 构建并启动全部服务
docker compose up -d --build

# 查看状态
docker compose ps

# 查看日志
docker compose logs -f backend
docker compose logs -f frontend

# 停止并移除容器（保留数据卷）
docker compose down

# 停止并删除数据卷（危险：会清空数据）
docker compose down -v
```

### 4.2 服务与端口

| 服务 | 容器名 | 端口映射 | 说明 |
| --- | --- | --- | --- |
| MySQL | elective-mysql | 3306:3306 | 首次启动自动执行 DDL 与初始化数据 |
| Redis | elective-redis | 6379:6379 | 开启 AOF 持久化 |
| 后端 | elective-backend | 8080:8080 | Spring Boot 服务 |
| 前端 | elective-frontend | 80:80 | Nginx 托管静态资源并代理 /api |

### 4.3 单独构建镜像

```bash
# 后端
cd backend
docker build -t elective-backend:1.0.0 .

# 前端
cd frontend
docker build -t elective-frontend:1.0.0 .
```

### 4.4 小程序端

小程序**无需容器部署**，由微信平台托管，只需指向后端地址：

1. 修改 `miniprogram/config/index.js` 的 `baseUrl` 为生产后端地址
   （**必须为 HTTPS**，微信要求 `request` 合法域名）；
2. 在微信公众平台 → 开发管理 → 服务器域名，把后端域名加入 `request` 合法域名；
3. 用微信开发者工具上传代码，提交审核后发布。

> ⚠️ 生产环境**不能**勾选「不校验合法域名」（该选项仅限本地开发），
> 因此后端必须提供 HTTPS 且域名已备案。
>
> 若后端经 Nginx 反向代理，注意 `/api` 前缀需与 `baseUrl` 保持一致。

### 4.5 自定义编排参数

生产环境建议通过 `.env` 文件覆盖 `docker-compose.yml` 中的默认密码：

```bash
# 项目根目录创建 .env
MYSQL_ROOT_PASSWORD=YourStrongPassword123!
REDIS_PASSWORD=YourRedisPassword456!
JWT_SECRET=YourJwtSecretAtLeast32CharactersLong!
```

> 同时需同步修改 `docker-compose.yml` 中对应的硬编码密码，或改为引用变量。

## 5. 生产环境部署建议

### 5.1 架构建议

```
                    ┌─────────────┐
    用户 ──────────▶│  Nginx/SLB  │ HTTPS 终止、负载均衡
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
       ┌──────▼─────┐ ┌────▼──────┐ ┌──▼────────┐
       │ 前端 Nginx │ │ 后端实例1 │ │ 后端实例2 │  无状态，可水平扩展
       └────────────┘ └────┬──────┘ └──┬────────┘
                           │            │
              ┌────────────┼────────────┘
              │            │
       ┌──────▼─────┐ ┌────▼──────┐
       │  MySQL     │ │  Redis    │
       │  主从/云DB  │ │ Sentinel  │
       └────────────┘ └───────────┘
```

### 5.2 安全加固清单

- [ ] 修改所有默认账号密码（含 `admin`、教师、学生演示账号）
- [ ] 通过环境变量设置强随机 `JWT_SECRET`（≥ 32 位）
- [ ] 数据库、Redis 不暴露公网端口，仅内网访问
- [ ] 生产环境 `knife4j.production=true`，关闭接口文档
- [ ] 启用 HTTPS，Nginx 配置证书与 HSTS
- [ ] 配置防火墙与安全组，仅开放 80/443
- [ ] 定期备份 MySQL 数据与 Redis 快照
- [ ] 应用日志接入集中式日志系统（ELK / Loki）
- [ ] 配置接口限流（Nginx `limit_req` 或网关层）

### 5.3 JVM 参数建议

```bash
java -Xms2g -Xmx2g \
     -XX:+UseG1GC \
     -XX:MaxGCPauseMillis=200 \
     -XX:+HeapDumpOnOutOfMemoryError \
     -XX:HeapDumpPath=/app/logs/heapdump.hprof \
     -Dfile.encoding=UTF-8 \
     -Duser.timezone=Asia/Shanghai \
     -jar college-elective-system.jar \
     --spring.profiles.active=prod
```

### 5.4 数据库优化建议

```sql
-- 连接数
SET GLOBAL max_connections = 500;

-- 慢查询日志
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 2;

-- 定期分析表（选课高峰期后）
ANALYZE TABLE course_selection;
ANALYZE TABLE course_grade;
ANALYZE TABLE course;
```

其他建议：

- `innodb_buffer_pool_size` 设置为物理内存的 50%-70%；
- 选课高峰期前执行 `POST /admin/courses/cache/preload` 预热缓存；
- `course_selection`、`course_grade`、`course_review` 与 `sys_log` 数据量增长较快，
  建议按月归档（`sys_log` 已有 `cleanExpiredLogs` 定时清理）。

### 5.5 Redis 优化建议

```
# redis.conf 关键配置
maxmemory 2gb
maxmemory-policy allkeys-lru
appendonly yes
save 900 1
save 300 10
```

> 注意：`elective:selection:switch` 与令牌白名单为业务关键数据，
> 若使用 `allkeys-lru` 策略，建议高负载下改用 `volatile-lru` 并为关键 Key 设置较长的过期时间。

## 6. 运维监控

### 6.1 健康检查

```bash
# 后端接口文档可用性（Dockerfile 已配置为该健康检查）
curl -f http://localhost:8080/api/v3/api-docs

# 前端
curl -I http://localhost/
```

### 6.2 日志位置

| 环境 | 路径 | 说明 |
| --- | --- | --- |
| 开发 | 控制台 + `logs/` | `college-elective-system.log` |
| 生产 | `/app/logs/` | 按天滚动，单文件 100MB，保留 30 天 |
| 错误日志 | `/app/logs/college-elective-system-error.log` | 仅 ERROR 级别，保留 60 天 |

### 6.3 关键监控指标

| 指标 | 说明 | 关注阈值 |
| --- | --- | --- |
| 选课接口 P99 耗时 | `/student/courses/*/select` | > 1000 ms 告警 |
| Redis 内存使用率 | `used_memory / maxmemory` | > 80% 告警 |
| Redis 选课 Key 数量 | `elective:course:capacity:*` | 异常波动需排查 |
| 数据库连接池使用率 | HikariCP active / max | > 80% 考虑扩容 |
| 登录失败次数 | `elective:auth:fail:*` | 突增可能遭遇暴力破解 |
| 慢查询数量 | MySQL slow log | 持续增长需优化索引 |

### 6.4 Redis 常用排查命令

```bash
# 选课相关 Key
redis-cli --scan --pattern "elective:course:capacity:*"

# 查看某课程余量
redis-cli GET elective:course:capacity:1

# 查看某课程已选学生
redis-cli SMEMBERS elective:course:selected:1

# 查看选课开关
redis-cli GET elective:selection:switch

# 查看在线令牌数
redis-cli --scan --pattern "elective:auth:token:*" | wc -l

# 内存使用
redis-cli INFO memory
```

## 7. 常见故障处理

### 7.1 后端启动失败

| 现象 | 排查方向 |
| --- | --- |
| `Communications link failure` | MySQL 未启动或连接串/账号错误 |
| `Unable to connect to Redis` | Redis 未启动或密码配置不匹配 |
| `Table 'xxx' doesn't exist` | 未执行 `schema.sql` |
| `Port 8080 was already in use` | 端口被占用，改用 `--server.port=8081` |
| `Access denied for user` | 数据库账号密码错误 |

### 7.2 选课异常

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示「选课通道已关闭」 | 开关关闭或不在选课窗口 | 检查 `elective:selection:switch` 与学期时间配置 |
| 提示「课程缓存尚未就绪」 | Redis 缺少余量 Key | 检查 Redis 连接，执行缓存预热 |
| 多选后人数与实际不符 | 数据不一致 | 调用 `POST /admin/courses/selection/sync` |
| 明明有余量却提示已满 | 缓存余量与 DB 不同步 | 执行同步接口，必要时清理该课程缓存 Key |
| 页面余量不刷新 | 浏览器缓存 | 前端已提供刷新按钮，或强制刷新页面 |

手动重置某课程缓存：

```bash
redis-cli DEL elective:course:capacity:1 elective:course:selected:1
# 下次选课请求会自动从数据库回源重建
```

### 7.3 登录异常

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示账号临时锁定 | 连续失败 5 次 | 等待 15 分钟，或 `redis-cli DEL elective:auth:fail:{username}` |
| 登录成功但立即失效 | Redis 数据被清空 | 检查 Redis 持久化配置 |
| 刷新页面被踢出 | 令牌过期 | 重新登录；确认前后端服务器时间同步 |

### 7.4 前端异常

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 接口 404 | 代理地址错误 | 检查 `VITE_PROXY_TARGET` 与后端 `context-path` |
| 跨域报错 | CORS 未放行 | 在 `elective.cors.allowed-origins` 添加前端域名 |
| 页面白屏 | 构建产物未更新 | 重新 `npm run build` 并清空浏览器缓存 |
| 刷新 404（生产） | Nginx 未配置 history 回退 | 确认 `try_files $uri $uri/ /index.html` |

### 7.5 小程序异常

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 请求被拦截，提示域名不合法 | 未配置 `request` 合法域名 | 在微信公众平台添加域名；本地开发可在开发者工具勾选「不校验合法域名」 |
| 登录后立即跳回登录页 | 令牌未正确保存或后端 401 | 检查 `config/index.js` 的 `baseUrl` 是否指向正确后端 |
| 真机调试接口失败，模拟器正常 | `baseUrl` 写成了 `localhost` | 改为电脑局域网 IP，并确保手机与电脑同网段 |
| 提示「小程序端目前仅供学生使用」 | 用了教师或管理员账号登录 | 小程序仅面向学生开放，请用学生账号 |

## 8. 数据备份与恢复

### 8.1 MySQL 备份

```bash
# 全量备份
mysqldump -uroot -p --single-transaction --routines --triggers \
  college_elective > backup_$(date +%Y%m%d).sql

# 仅备份关键表
mysqldump -uroot -p college_elective course course_selection course_grade > core_$(date +%Y%m%d).sql

# 恢复
mysql -uroot -p college_elective < backup_20260911.sql
```

### 8.2 Redis 备份

```bash
# 触发 RDB 快照
redis-cli BGSAVE

# 复制备份文件
cp /var/lib/redis/dump.rdb /backup/redis_dump_$(date +%Y%m%d).rdb
```

> **重要**：Redis 中保存了令牌白名单与选课余量。若 Redis 完全丢失，
> 用户需重新登录，选课余量会在下次请求时自动从数据库回源重建。

### 8.3 定时备份建议

```bash
# /etc/crontab 示例：每日凌晨 2 点备份
0 2 * * * root mysqldump -uroot -pPASSWORD --single-transaction college_elective | gzip > /backup/db_$(date +\%Y\%m\%d).sql.gz
0 3 * * * root redis-cli BGSAVE && cp /var/lib/redis/dump.rdb /backup/redis_$(date +\%Y\%m\%d).rdb
0 4 * * 0 root find /backup -name "*.sql.gz" -mtime +30 -delete
```

## 9. 升级与回滚

### 9.1 升级流程

```bash
# 1. 备份数据库与 Redis
mysqldump -uroot -p college_elective > pre_upgrade.sql
redis-cli BGSAVE

# 2. 停止服务
docker compose down

# 3. 更新代码并重新构建
git pull
docker compose up -d --build

# 4. 验证
curl -f http://localhost:8080/api/v3/api-docs
docker compose logs -f backend
```

### 9.2 回滚

```bash
# 回退到指定版本镜像
docker compose down
docker tag elective-backend:1.0.0 elective-backend:current
docker compose up -d

# 如需回滚数据
mysql -uroot -p college_elective < pre_upgrade.sql
```
