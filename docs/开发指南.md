# 开发指南

> 面向参与本项目的开发者，说明开发环境准备、编码规范、开发流程与扩展方式。

## 1. 开发环境准备

### 1.1 必装软件

| 软件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 21 | 后端运行与编译 |
| Maven | 3.8+ | 后端依赖管理与构建 |
| Node.js | 18+ | 前端构建 |
| MySQL | 8.0+ | 数据库 |
| Redis | 6.0+ | 缓存 |
| IDE | IntelliJ IDEA 2023+ / VS Code | 开发工具 |

### 1.2 IDE 必要配置

**IntelliJ IDEA**

1. 启用注解处理：`Settings → Build, Execution, Deployment → Compiler → Annotation Processors → Enable annotation processing`
2. 安装插件：Lombok、MyBatisX（可选，便于 XML 与 Mapper 跳转）
3. 设置文件编码为 UTF-8：`Settings → Editor → File Encodings`
4. 导入代码风格：项目已提供 `.editorconfig` 风格约定（4 空格缩进，UTF-8）

**VS Code（前端）**

推荐插件：

- Vue - Official（Volar）
- ESLint
- SCSS IntelliSense
- Auto Rename Tag

### 1.3 启动顺序

```
MySQL 启动 → Redis 启动 → 后端启动 → 前端启动
```

## 2. 编码规范

### 2.1 后端规范

#### 命名

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 类 | 大驼峰 | `CourseSelectionService` |
| 接口 | 大驼峰，不带 I 前缀 | `CourseService` |
| 实现类 | 接口名 + Impl | `CourseServiceImpl` |
| 方法 | 小驼峰，动词开头 | `selectCourse`、`pageCourses` |
| 常量 | 全大写下划线 | `COURSE_STATUS_NORMAL` |
| 包 | 全小写 | `com.college.elective.service.impl` |
| 布尔字段 | 不加 is 前缀（实体） | `selectable`、`enabled` |

#### 分层约定

```java
// Controller：只做校验、调用、组装响应
@Operation(summary = "选课")
@OperationLog(module = "选课", operation = "学生选课")
@PostMapping("/courses/{courseId}/select")
public Result<SelectionResultVO> selectCourse(@PathVariable Long courseId) {
    return Result.success("选课成功", selectionService.selectCourse(courseId));
}

// Service：承载业务逻辑，明确事务边界
@Override
@Transactional(rollbackFor = Exception.class)
public void createCourse(CourseDTO dto) {
    validateCourseCodeUnique(dto.getCourseCode(), dto.getSemesterId(), null);
    validateScheduleConflict(dto);
    // ...
}

// Mapper：只做数据访问，复杂查询放 XML
IPage<Course> selectCoursePage(IPage<Course> page, @Param("query") CourseQueryDTO query);
```

#### 注释规范

类与公共方法需使用 Javadoc，说明用途、参数与关键约束：

```java
/**
 * 学生选课（Redis 原子预占 + 时间冲突校验 + 落库）。
 *
 * @param courseId 课程ID
 * @return 选课结果，包含最新剩余容量
 * @throws BusinessException 课程不存在、余量不足、时间冲突等情况
 */
SelectionResultVO selectCourse(Long courseId);
```

#### 异常处理

```java
// 推荐：使用业务异常 + 状态码枚举
BusinessException.throwIf(course == null, ResultCode.COURSE_NOT_FOUND);

// 推荐：条件断言 + 自定义提示
if (conflicts.isEmpty()) {
    throw new BusinessException(ResultCode.COURSE_TIME_CONFLICT, buildConflictMessage(conflicts));
}

// 禁止：吞掉异常或直接返回 null
// catch (Exception e) { }
```

#### 常用工具

```java
// 当前登录用户
Long studentId = SecurityUtils.requireStudentId();
LoginUser loginUser = SecurityUtils.getLoginUser();

// 条件构造器（推荐 Lambda 形式）
list(Wrappers.<Course>lambdaQuery()
        .eq(Course::getSemesterId, semesterId)
        .eq(Course::getStatus, Constants.COURSE_STATUS_NORMAL));

// Redis Key 统一从 RedisKeys 取
stringRedisTemplate.opsForValue().get(RedisKeys.COURSE_CAPACITY + courseId);
```

### 2.2 前端规范

#### 命名

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 组件文件 | 小写中划线 | `course-card.vue` |
| 页面文件 | 语义化小写 | `courses.vue`、`timetable.vue` |
| 变量/函数 | 小驼峰 | `courseList`、`loadData` |
| 常量 | 全大写下划线 | `COURSE_TYPE_OPTIONS` |
| 组件名 | 大驼峰（defineOptions） | `defineOptions({ name: 'StudentCourses' })` |

#### 页面结构模板

```vue
<template>
  <div class="page-container">
    <!-- 搜索区 -->
    <div class="search-bar">...</div>

    <!-- 内容区 -->
    <el-card shadow="never">
      <template #header>
        <div class="card-header"><span>标题</span></div>
      </template>
      <!-- 表格/列表 -->
    </el-card>
  </div>
</template>

<script setup>
import { onMounted, reactive, ref } from 'vue'
import { ElMessage } from 'element-plus'
import { pageCourses } from '@/api/admin'
import { courseTypeText } from '@/utils/dict'

defineOptions({ name: 'AdminCourses' })

const loading = ref(false)
const list = ref([])

onMounted(loadData)

async function loadData() {
  loading.value = true
  try {
    const { data } = await pageCourses({ pageNum: 1, pageSize: 10 })
    list.value = data.records || []
  } finally {
    loading.value = false
  }
}
</script>

<style lang="scss" scoped>
.page-container { }
</style>
```

#### 关键约定

- **样式作用域**：组件样式一律使用 `<style lang="scss" scoped>`；
- **字典统一**：状态文本与标签颜色统一从 `@/utils/dict` 引入，禁止在页面中硬编码；
- **请求封装**：所有接口调用通过 `@/api/*` 模块，禁止在组件中直接使用 axios；
- **错误处理**：请求拦截器已统一提示错误，组件中仅需 `try/finally` 管理 loading；
- **状态管理**：跨页面共享数据放 Pinia，页面局部状态用 `ref`/`reactive`。

## 3. 开发流程

### 3.1 分支策略

```
master         生产分支，仅接受来自 develop 的合并
develop        开发主干
feature/xxx    功能开发分支，从 develop 切出
hotfix/xxx     紧急修复，从 master 切出并同时合回 develop
```

```bash
# 开始新功能
git checkout develop
git pull
git checkout -b feature/course-export

# 完成后合并
git checkout develop
git merge --no-ff feature/course-export
git push
```

### 3.2 提交信息规范

遵循 Conventional Commits：

```
feat: 新增课程数据导出功能
fix: 修复并发选课时余量缓存不同步的问题
docs: 补充部署文档中的 Redis 配置说明
```

## 4. 常见开发任务

### 4.1 新增一个业务模块

> ✅ **已有现成范例**：教学评价模块（`CourseReview*`）是一套完整的端到端实现，
> 覆盖建表、实体、Mapper、Service、Controller 与前端三端页面，
> 可作为新增模块时的**最佳参考**。下文即以其为例说明标准步骤。

**后端**

1. 在 `db/schema.sql` 增加表定义（并在文件头 `DROP TABLE` 清单中补一行）；
2. 创建实体 `entity/Xxx.java`；
   ⚠️ **默认继承 `BaseEntity`**（自动获得 `create_time` / `update_time` /
   `deleted` 逻辑删除）。**仅当该表不设 `deleted` 列时才不继承**，
   评价表 `CourseReview` 属于这种情况，详见 [数据库设计 3.14](./数据库设计.md#314-course_review-课程评价)；
3. 创建 `mapper/XxxMapper.java`，复杂查询补充 `resources/mapper/XxxMapper.xml`；
4. 创建 `dto/XxxDTO.java`、`vo/XxxVO.java`；
   ⚠️ **禁止把实体直接返回给前端**，尤其涉及匿名或脱敏字段时必须在 VO 层过滤；
5. 创建 `service/XxxService.java` 与 `impl/XxxServiceImpl.java`；
6. 创建 `controller/XxxController.java`；
   建议按角色拆分（如评价模块拆为 `StudentReviewController` /
   `TeacherReviewController` / `AdminReviewController`），
   以便直接复用 `SecurityConfig` 中的 URL 前缀权限；
7. 如涉及缓存，在 `RedisKeys` 中补充 Key 常量；
8. 在 `Constants` 中补充状态枚举，在 `ResultCode` 中补充业务状态码。

**前端**

1. 在 `api/` 下新增或扩展接口模块；
2. 在 `router/index.js` 增加路由，配置 `meta.title`、`meta.icon`、`meta.roles`；
3. 在 `views/` 下创建页面；
4. 在 `utils/dict.js` 补充相关字典。

**小程序（可选）**

若该功能面向学生，可在 `miniprogram/` 下同步实现：
1. 在 `api/` 增加接口封装；
2. 在 `app.json` 的 `pages` 注册页面；
3. 在 `pages/` 下创建页面（WXML / WXSS / JS / JSON 四件套）。

### 4.4 新增缓存

```java
// 1. 在 RedisKeys 中定义 Key
public static final String COURSE_RATING = PREFIX + "course:rating:";

// 2. 读写缓存
String key = RedisKeys.COURSE_RATING + courseId;
String cached = stringRedisTemplate.opsForValue().get(key);
if (cached != null) {
    return Integer.parseInt(cached);
}
int rating = computeRating(courseId);
stringRedisTemplate.opsForValue().set(key, String.valueOf(rating),
        RedisKeys.DEFAULT_CACHE_MINUTES, TimeUnit.MINUTES);
return rating;

// 3. 数据变更时清理缓存
stringRedisTemplate.delete(RedisKeys.COURSE_RATING + courseId);
```

**批量读取（列表场景）**：列表页需要取多门课程的缓存值时，
用 `multiGet` 一次取回，避免 N 次往返；缺失的 Key 返回 `null`，需回退到数据库兜底：

```java
List<String> keys = courseIds.stream()
        .map(id -> RedisKeys.COURSE_CAPACITY + id).toList();
List<String> values = stringRedisTemplate.opsForValue().multiGet(keys);
// values 顺序与 keys 一一对应，不存在时为 null
```

**Lua 脚本中的 TTL**：`select_course.lua` / `drop_course.lua` 接收
`ARGV[2] = ttlSeconds`，调用时传入 `RedisKeys.DEFAULT_CACHE_SECONDS`，
使容量 Key 与已选集合 Key 保持同一过期时间：

```java
stringRedisTemplate.execute(selectCourseScript,
        List.of(capacityKey, selectedKey),
        String.valueOf(studentId),
        String.valueOf(RedisKeys.DEFAULT_CACHE_SECONDS));
```

## 5. 调试技巧

### 5.1 后端调试

**查看 SQL 执行**：开发环境已在 `application-dev.yml` 开启控制台 SQL 日志：

```yaml
mybatis-plus:
  configuration:
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
```

**调整日志级别**：

```yaml
logging:
  level:
    com.college.elective: debug
    org.springframework.security: debug   # 排查认证问题
```

**在 IDEA 中调试**：直接在 Controller 方法行号处打断点，以 Debug 模式运行 `CollegeElectiveApplication`。

### 5.2 前端调试

**查看请求**：浏览器 DevTools → Network，关注 `/api/**` 请求与响应结构。

**代理排查**：若接口 404，检查 `vite.config.js` 中的 proxy 配置与后端 `context-path`。

**状态调试**：Vue DevTools 中检查 Pinia store 的 `user` 与 `app`。

### 5.3 并发选课压测

```bash
# 使用 ab 压测选课接口（需先准备一批不同用户的 token）
ab -n 1000 -c 100 -H "Authorization: Bearer {token}" \
   -p select.json -T application/json \
   http://localhost:8080/api/student/courses/1/select
```

**验证要点**：

1. 成功选课数不超过课程容量；
2. 数据库 `course_selection` 无重复记录；
3. Redis 余量 + 已选集合大小 = 课程最大容量；
4. `course.selected_count` 与真实选课数一致（同步任务执行后）。

### 6.2 测试约定

- 纯算法逻辑（如冲突检测）使用单元测试，不依赖 Spring 上下文；
- 涉及数据库与 Redis 的测试使用 `@SpringBootTest` + `@Transactional` 自动回滚；
- 测试类命名以 `Tests` 结尾，方法名使用 `@DisplayName` 描述中文场景。

示例：

```java
@Test
@DisplayName("单双周同一时段互不冲突")
void oddEvenWeekNoConflict() {
    assertFalse(isConflict(1, 1, 2, 1, 16, "ODD",
                1, 1, 2, 1, 16, "EVEN"));
}
```

## 7. 性能优化建议

| 场景 | 优化手段 |
| --- | --- |
| 选课接口 | Redis Lua 原子操作；避免在预占后做重量级查询 |
| 课程列表 | 分页 + 索引；余量批量从 Redis 读取（`multiGet`） |
| 成绩查询 | 按 `student_id + semester_id` 建索引；成绩单一次查询聚合 |
| 日志写入 | 异步线程池 + `CallerRunsPolicy` 防丢失 |
| 统计接口 | 结果缓存；避免高频调用 |
| 前端首屏 | 路由懒加载 + 依赖分包（已配置 manualChunks） |
