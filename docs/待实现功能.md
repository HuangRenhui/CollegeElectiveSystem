**已实现方法说明**（第 3、5、6 项）：

- `checkConflict` —— 时间冲突预检，无副作用，供选课前提示使用：
  1. 通过 `SecurityUtils.requireStudentId()` 取当前学生，学生ID取自登录态，
     不接受请求参数，避免越权查询他人课表；
  2. 取当前学期并**判空**：`selectByStudentSelection` 的 SQL 中
     `cs.semester_id = #{semesterId}` 为硬编码条件，若传入 `null` 将查不到任何数据，
     导致冲突检测静默失效，故此处抛出 `CURRENT_SEMESTER_NOT_SET(5005)`；
  3. 分别查询目标课程排课与本人本学期已选课程排课（SQL 已限定 `status = 1`）；
  4. 两两比对，**跳过课程ID相同的记录**（学生已选该课时两侧会同时出现，自己与自己必然判定冲突）；
  5. 命中冲突时构造 `ConflictVO`，时间信息由 `sectionText`（如「第1-2节」）与
     `weekText`（如「第1-16周」）两个字段分别承载。

- `pageMySelections` —— 通过 `SecurityUtils.requireStudentId()` 取当前学生，调用
  `CourseSelectionMapper#selectStudentSelections` 分页查询。
- `pageCourseStudents` —— 先经 `checkCourseAccess` 校验访问权限（管理员不受限，
  教师仅能查看自己授课的课程，越权返回 403），再调用
  `CourseSelectionMapper#selectCourseStudents` 分页查询。

> 这三个方法属纯查询与计算，无并发与事务要求，已按标准增删查改实现。

**冲突判定算法**：已提取至 `common/ScheduleConflictUtils`，供选课预检
（本方法）与排课校验（`CourseServiceImpl#validateScheduleConflict`）共用，
避免两处分别实现导致行为不一致。该工具类按**星期、节次、周次、周类型**四个维度判定，
其中周类型规则为：任一方为 `ALL` 或两者类型相同则周次相交即冲突；
`ODD` 与 `EVEN` 需在公共周次区间内存在同奇偶的周次才算冲突
（例如 ODD 第 1-8 周与 EVEN 第 5-12 周在第 6、8 周重叠，仍判定冲突）。

### 2.2 涉及的业务规则

#### 规则 1：选课开关校验

需依次校验四处，任一不通过即拒绝选课：

| 校验项 | 数据来源 | 失败状态码 |
| --- | --- | --- |
| 全局配置开关 | `elective.selection.enabled`（配置类 `ElectiveProperties`） | 3007 |
| 动态开关 | Redis `elective:selection:switch`（值为 `off` 时关闭） | 3007 |
| 学期状态 | 当前学期 `semester.status`（见下方说明） | 3006 |
| 选课时间窗口 | 当前学期 `semester.select_start_time / select_end_time` | 3006 |

> 当前学期通过 `semester.is_current = 1` 查询。

**关于 `status` 字段**：`Semester#status` 取值为 `0-未开始 / 1-选课中 / 2-进行中 / 3-已结束`。
选课仅允许在 `status = 1` 时进行，建议与时间窗口校验**取交集**，即两者都通过才放行：

```java
// semester.status = 1 且 时间窗口内
if (semester.getStatus() == null || semester.getStatus() != 1) {
    throw new BusinessException(ResultCode.SELECTION_NOT_OPEN, "当前学期未开放选课");
}
if (!semester.inSelectionPeriod()) {
    throw new BusinessException(ResultCode.SELECTION_NOT_OPEN, "当前不在选课时间段内");
}
```

**可直接复用的现成方法**：`Semester#inSelectionPeriod()`（`entity/Semester.java:58`）已实现完整的时间窗口判定：

```java
public boolean inSelectionPeriod() {
    LocalDateTime now = LocalDateTime.now();
    return selectStartTime != null && selectEndTime != null
            && !now.isBefore(selectStartTime) && !now.isAfter(selectEndTime);
}
```

无需重复编写时间比较逻辑，直接调用即可。

> **注意**：`status` 由管理员在学期管理页手工维护，`inSelectionPeriod()` 依据时间自动判定，
> 两者可能不一致（例如管理员忘记改 `status`，但时间已到）。当前设计采用**交集**（都满足才可选课），
> 若希望「时间到了就自动开放」，需改为**并集**或由定时任务同步 `status`，实现时请明确取舍。

#### 规则 2：课程状态校验

- 课程不存在或已逻辑删除 → `3001`
- `course.status != 1`（下架或已结课）→ `3001`

#### 规则 3：学分上限校验

```
本学期已选学分（sumSelectedCredit）+ 本次课程学分 > elective.selection.max-credit
    → 抛出 3008，提示「选课后总学分将达到 X，超过本学期上限 Y 学分」
```

已选学分通过 `CourseSelectionMapper.sumSelectedCredit(studentId, semesterId)` 计算。

#### 规则 4：时间冲突检测（核心）

**四维判定**，四条全部满足才判定为冲突：

| 维度 | 判定条件 |
| --- | --- |
| 星期 | `dayOfWeek` 相同 |
| 节次 | `startA <= endB && endA >= startB` |
| 周次 | `[startWeekA, endWeekA]` 与 `[startWeekB, endWeekB]` 有交集 |
| 周类型 | 见下方说明 |

**周类型兼容规则**：

- 一方为 `ALL`（每周）→ 冲突
- 双方类型相同（都是 `ODD` 或都是 `EVEN`）→ 冲突
- 一方 `ODD` 一方 `EVEN` → 仅当存在**同为奇/偶数**的公共周次时冲突（遍历公共周次区间判断）

**数据获取**：

```java
// 目标课程的排课
List<CourseSchedule> targetSchedules = scheduleMapper.selectByCourseId(courseId);

// 该学生本学期已选课程的排课
List<CourseSchedule> selectedSchedules =
        scheduleMapper.selectByStudentSelection(studentId, semesterId);
```

**返回结构**：每个冲突构造成 `ConflictVO`，包含冲突课程名、节次描述、周次描述。

> 📌 **算法参考**：`src/test/java/com/college/elective/ScheduleConflictTests.java`
> 中已有 7 个测试用例覆盖边界场景（同天重叠、周次不重叠、单双周互斥等），
> 其 `isConflict` 方法可直接作为实现参照。

#### 规则 5：Redis 原子预占（核心）

**步骤**：

1. 计算 Redis Key：
   ```java
   String capacityKey = RedisKeys.COURSE_CAPACITY + courseId;  // elective:course:capacity:{id}
   String selectedKey = RedisKeys.COURSE_SELECTED + courseId;  // elective:course:selected:{id}
   ```
2. **确保缓存就绪**：若 `capacityKey` 不存在，需从数据库回源重建（建议加锁 + 双重检查）
3. **执行 Lua 脚本**：
   ```java
   Long result = stringRedisTemplate.execute(
           selectCourseScript,                       // RedisConfig 已注册的 Bean
           List.of(capacityKey, selectedKey),
           String.valueOf(studentId));
   ```

**Lua 返回值语义**（已定义在 `select_course.lua`）：

| 返回值 | 含义 | 对应处理 |
| --- | --- | --- |
| `0` | 预占成功 | 继续落库 |
| `1` | 已选过该课程 | 抛出 3003 |
| `2` | 余量不足 | 抛出 3002 |
| `3` | 缓存未初始化 | 抛出 3010 |

#### 规则 6：落库与回滚

```
预占成功
    ↓
写入选课记录（事务）
    ├─ 已有记录且 status=1  → 抛出 3003
    ├─ 已有记录且 status=0  → 复用记录，置 status=1、更新 selectTime、清空 dropTime
    └─ 无记录               → 新增记录，status=1、selectType=1
    ↓
成功 → courseMapper.increaseSelectedCount(courseId)
失败 → 回滚 Redis 预占（执行 drop_course.lua，归还余量 + 移除已选标记）
```

> ⚠️ **重要**：由于事务方法需通过代理调用，建议在 Service 中注入
> `ObjectProvider<CourseSelectionServiceImpl>` 获取自身代理，或将落库逻辑抽到独立 Bean，
> 避免 `this.persistSelection()` 自调用导致 `@Transactional` 失效。

#### 规则 7：退课

**前置校验**：

| 校验项 | 失败状态码 |
| --- | --- |
| 课程 `selectable != 1`（不允许退选） | 3009 |
| 未找到 `status = 1` 的选课记录 | 3004 |
| 该选课记录 `score != null`（已录入成绩） | 3009 |

**执行步骤**：

1. 更新选课记录：`status = 0`、`dropTime = now()`
2. 执行 `drop_course.lua` 归还 Redis 余量
3. `courseMapper.decreaseSelectedCount(courseId)`

> 注意：退课**不删除记录**，便于审计与重新选课复用。

#### 规则 8：缓存预热与同步

**`preloadCourseCache(semesterId)`**：

### 2.5 前端时间依赖问题（待优化）

**现状**：学生端选课倒计时组件 `frontend/src/utils/useSelectionCountdown.js` 直接使用浏览器本地时间
（`new Date()`）解析 `semester.selectStartTime / selectEndTime`，因此倒计时的准确性**依赖学生本机系统时间**。

**存在的问题**：

| 风险 | 影响 |
| --- | --- |
| 学生手动修改本机时间 | 倒计时显示失真，可能提前显示「已开放」或延迟显示 |
| 学生电脑时间未同步（时区/漂移） | 同上 |
| 跨时区访问 | 解析结果与服务器不一致 |

**安全说明**：此问题**仅影响前端展示与按钮可用状态，不构成安全漏洞**。
只要后端按「规则 1」正确校验 `status` 与 `inSelectionPeriod()`，即使前端被绕过，选课请求依然会被拒绝。
因此该问题属于**体验/公平性优化**，非阻塞性缺陷。

**建议的改进方案**（实现时二选一）：

**方案 A：后端下发服务器时间（推荐，改动小）**

1. 在 `Result` 或响应头中附带服务器当前时间戳；
2. 前端首次请求时记录 `serverTime` 与 `localTime` 的差值 `offset`；
3. 倒计时改用 `Date.now() + offset` 作为"当前时间"。

```js
// 前端伪代码
const offset = serverTimestamp - Date.now()
const currentTime = Date.now() + offset   // 替代 new Date()
```

**方案 B：后端直接下发剩余毫秒数**

在学期查询接口中额外返回 `selectionCountdownMs`（距离选课开始或结束的剩余毫秒），
由服务端计算，前端仅做递减展示。此方案前端无需关心时间解析，但需新增接口字段。

**建议实现时机**：与选课模块后端实现一并完成，避免前端二次改动。

### 2.6 教务代选（管理员）

#### 2.6.1 业务背景

代选功能用于处理学生**通过正常渠道无法完成选课**的特殊情况。参照高校教务的实际做法：

| 场景 | 实际处理方 | 真实做法 |
| --- | --- | --- |
| 学生错过选课时间 | 学生本人 → 教务员 | 学生提交申请，**教务员代选** |
| 必修课名单缺失 | 教务系统自动 | 系统按专业自动导入，不依赖人工 |
| 重修 / 插班 | 教务处 | 统一处理，单独走重修流程 |

> **教师端不提供代选能力**。教师对本课程学生的权限仅限：查看名单、导出名单、录入成绩。
> 这与高校实际一致——教师直接改名单会绕过学分、冲突、容量等校验，属于教学事故风险。

#### 2.6.3 校验规则（核心）

代选与普通选课的**关键差异**在于时间窗口，其余校验**一个都不能少**：

| 校验项 | 普通选课 | 教务代选 | 失败状态码 |
| --- | --- | --- | --- |
| 全局配置开关 `elective.selection.enabled` | ✅ 校验 | ❌ **跳过** | - |
| Redis 动态开关 `selection-switch` | ✅ 校验 | ❌ **跳过** | - |
| 学期 `status` 与选课时间窗口 | ✅ 校验 | ❌ **跳过** | - |
| 课程状态 `course.status = 1` | ✅ 校验 | ✅ **保留** | 3001 |
| 重复选课（`status = 1` 已存在） | ✅ 校验 | ✅ **保留** | 3003 |
| 学分上限 | ✅ 校验 | ✅ **保留** | 3008 |
| 上课时间冲突 | ✅ 校验 | ✅ **保留** | 3005 |
| 课程容量上限 | ✅ 校验 | ✅ **保留** | 3002 |
| 已录入成绩不可退选 | ✅ 校验 | ✅ **保留** | 3009 |

> **设计理由**：教务员代选本就是为「补救已过期的选课需求」而设，若仍受时间窗口限制则该功能失去意义。
> 权限风险通过 `select_type = 2` 留痕 + 操作日志来管控，而非通过时间卡口。

**代选专属规则**：

1. **必须填写代选原因**（`reason`），长度不少于 2 个字符，随操作日志一并落库，供后续审计追溯；
2. **容量已满时拒绝**，需管理员先扩容或由学生申请其他课程；
3. **写入选课记录时 `select_type` 置为 2**，用于区分正常选课与代选；
4. 被代选的学生若已有 `status = 0`（已退选）的历史记录，**复用该记录**：置 `status = 1`、更新 `select_time`、清空 `drop_time`、`select_type` 置 2。

#### 2.6.4 参考实现流程

```
adminAddSelection(studentId, courseId, reason)
  ↓
1. 校验 reason 非空且长度 ≥ 2        → 否则 参数错误
2. 校验学生存在且账号未被禁用         → 否则 学生不存在
3. 校验课程存在且 status = 1          → 否则 3001
4. 校验该学生本学期选课数 / 学分上限  → 否则 3008
5. 校验课程余量 > 0（读 Redis，兜底读库）→ 否则 3002
6. 时间冲突预检（四维判定）           → 冲突时抛 3005，由管理员二次确认后重试
  ↓
7. 写入选课记录（事务）
     ├─ 已有 status=1 记录 → 抛 3003
     ├─ 已有 status=0 记录 → 复用，置 status=1、selectType=2、清空 dropTime
     └─ 无记录             → 新增，status=1、selectType=2
  ↓
8. 更新 course.selected_count，并同步 Redis 余量
  ↓
9. 记录操作日志（含 reason）
```

### 3.2 涉及的业务规则

#### 规则 1：成绩计算

**总评成绩**：

```
总评 = 平时成绩 × 0.3 + 期末成绩 × 0.7
```

**单边缺失时的折算**：

| 平时 | 期末 | 总评 |
| --- | --- | --- |
| 有 | 有 | `usual × 0.3 + exam × 0.7` |
| 有 | 无 | `usual` |
| 无 | 有 | `exam` |
| 无 | 无 | `null` |

结果保留 1 位小数（`RoundingMode.HALF_UP`）。

**绩点换算（4.0 制分段）**：

| 总评区间 | 绩点 |
| --- | --- |
| ≥ 90 | 4.0 |
| 85-89 | 3.7 |
| 82-84 | 3.3 |
| 78-81 | 3.0 |
| 75-77 | 2.7 |
| 72-74 | 2.3 |
| 68-71 | 2.0 |
| 64-67 | 1.5 |
| 60-63 | 1.0 |
| < 60 | 0.0 |

**及格判定**：总评 ≥ 60（`Constants.PASS_SCORE`）记为及格，`is_pass = 1`。

#### 规则 2：成绩取值范围

- 平时成绩、期末成绩均须在 **0-100** 之间，否则抛出 `4003`；
- 允许为 `null`（表示暂未录入该项）。

#### 规则 3：状态流转

```
草稿(0) ──发布──▶ 已发布(1) ──归档──▶ 已归档(2)
   ▲                  │
   └──────撤回────────┘
```

| 状态 | 常量 | 能否修改成绩 |
| --- | --- | --- |
| 草稿 | `GRADE_STATUS_DRAFT = 0` | ✅ 可修改 |
| 已发布 | `GRADE_STATUS_PUBLISHED = 1` | ❌ 需先撤回（抛 4002） |
| 已归档 | `GRADE_STATUS_ARCHIVED = 2` | ❌ 需先撤回（抛 4002） |

#### 规则 4：权限校验

```java
// 管理员可直接操作；教师仅能操作自己授课的课程
private void checkTeacherPermission(Course course) {
    LoginUser loginUser = SecurityUtils.getLoginUser();
    if (loginUser.isAdmin()) {
        return;
    }
    if (!course.getTeacherId().equals(loginUser.getTeacherId())) {
        throw new BusinessException(ResultCode.NOT_COURSE_TEACHER);  // 4004
    }
}
```

#### 规则 5：录入逻辑（`inputGrades`）

**流程**：

1. 校验 `courseId` 非空，查询课程并做权限校验；
2. 遍历 `dto.getItems()`：
   - 校验成绩范围；
   - **定位选课记录**：优先用 `selectionId`，其次用 `studentId`（需 `course_id` + `status = 1`）；
   - 查询是否已有成绩记录（按 `selectionId` 唯一）：
     - 已发布/已归档 → 抛出 `4002`；
     - 新增时初始化 `studentId`/`courseId`/`semesterId`/`status = 0`；
   - 计算总评与绩点，设置 `inputTime`、`inputBy`；
   - 保存（`saveOrUpdate`）；
   - **同步**：将总评写回 `course_selection.score`，便于学生端快速展示。

#### 规则 6：发布逻辑（`publishGrades`）

**前置条件**：

- 权限校验通过；
- 课程存在草稿状态的成绩记录，否则抛「暂无可发布的成绩记录」；
- **所有草稿记录的总评成绩均不为 `null`**，否则抛出：
  ```
  还有 N 名学生未录入成绩，无法发布
  ```

**执行**：

1. 批量将草稿记录置为已发布，设置 `publishTime`；
2. **数据联动**：将对应选课记录 `status` 从 `1`（已选课）改为 `2`（已修完）。

> ⚠️ 注意：`course_selection` 状态改为 2 后，「我的选课」与课表查询的过滤条件
> 可能需要同步调整（课表查询当前只查 `status = 1`）。

#### 规则 7：撤回逻辑（`revokeGrades`）

- 权限校验；
- 将已发布记录改回草稿，清空 `publishTime`；
- 建议同时将选课记录状态从 `2` 改回 `1`（保持数据一致）。

#### 规则 8：成绩单统计（`getStudentGradeReport`）

**查询**：`CourseGradeMapper.selectStudentGrades(studentId, semesterId, publishedOnly = true)`
（仅统计已发布成绩）。

**统计项**：

| 指标 | 计算方式 |
| --- | --- |
| `totalCredit` | 所有课程学分求和 |
| `earnedCredit` | 仅及格课程的学分求和 |
| `averageScore` | 所有有总评成绩的课程的算术平均，保留 2 位小数 |
| `averageGradePoint` | `Σ(绩点 × 学分) / Σ(学分)`，保留 2 位小数 |
