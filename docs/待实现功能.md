### 1.4 运行期行为说明

**应用可正常启动运行**：Controller 通过 `ObjectProvider<XxxService>` 延迟获取 Service，
因此在其实现类缺失时不会导致 Spring 容器启动失败。

调用未实现接口时，返回统一业务提示（HTTP 200，业务码 `5006`）：

```json
{
  "code": 5006,
  "message": "学生选课 尚未实现，请参考 docs/待实现功能.md",
  "success": false
}
```

相关工具类：`com.college.elective.common.PendingFeature`，提供两种用法：

```java
// 方式一：返回「尚未实现」响应
CourseSelectionService service = selectionServiceProvider.getIfAvailable();
if (service == null) {
    return PendingFeature.result("学生选课");
}
return Result.success(service.selectCourse(courseId));

// 方式二：抛出「尚未实现」业务异常
CourseSelectionService service = PendingFeature.require(selectionServiceProvider, "学生选课");
```

### 1.5 实现完成后的替换方式

将 Controller 中的 `getIfAvailable()` 判空分支移除，直接注入 Service 并调用即可：

```java
// 改造前
private final ObjectProvider<CourseSelectionService> selectionServiceProvider;

// 改造后
private final CourseSelectionService selectionService;
```

### 2.2 涉及的业务规则

#### 规则 1：选课开关校验

需依次校验三处，任一不通过即拒绝选课：

| 校验项 | 数据来源 | 失败状态码 |
| --- | --- | --- |
| 全局配置开关 | `elective.selection.enabled`（配置类 `ElectiveProperties`） | 3007 |
| 动态开关 | Redis `elective:selection:switch`（值为 `off` 时关闭） | 3007 |
| 选课时间窗口 | 当前学期 `semester.select_start_time / select_end_time` | 3006 |

> 当前学期通过 `semester.is_current = 1` 查询。

#### 规则 2：课程状态校验

- 课程不存在或已逻辑删除 → `3001`
- `course.status != 1`（下架或已结课）→ `3001`

#### 规则 3：学分上限校验

```
本学期已选学分（sumSelectedCredit）+ 本次课程学分 > elective.selection.max-credit
    → 抛出 3008，提示「选课后总学分将达到 X，超过本学期上限 Y 学分」
```

已选学分通过 `CourseSelectionMapper.sumSelectedCredit(studentId, semesterId)` 计算。

#### 规则 4：时间冲突检测（核心）

**四维判定**，四条全部满足才判定为冲突：

| 维度 | 判定条件 |
| --- | --- |
| 星期 | `dayOfWeek` 相同 |
| 节次 | `startA <= endB && endA >= startB` |
| 周次 | `[startWeekA, endWeekA]` 与 `[startWeekB, endWeekB]` 有交集 |
| 周类型 | 见下方说明 |

**周类型兼容规则**：

- 一方为 `ALL`（每周）→ 冲突
- 双方类型相同（都是 `ODD` 或都是 `EVEN`）→ 冲突
- 一方 `ODD` 一方 `EVEN` → 仅当存在**同为奇/偶数**的公共周次时冲突（遍历公共周次区间判断）

**数据获取**：

```java
// 目标课程的排课
List<CourseSchedule> targetSchedules = scheduleMapper.selectByCourseId(courseId);

// 该学生本学期已选课程的排课
List<CourseSchedule> selectedSchedules =
        scheduleMapper.selectByStudentSelection(studentId, semesterId);
```

**返回结构**：每个冲突构造成 `ConflictVO`，包含冲突课程名、节次描述、周次描述。

> 📌 **算法参考**：`src/test/java/com/college/elective/ScheduleConflictTests.java`
> 中已有 7 个测试用例覆盖边界场景（同天重叠、周次不重叠、单双周互斥等），
> 其 `isConflict` 方法可直接作为实现参照。

#### 规则 5：Redis 原子预占（核心）

**步骤**：

1. 计算 Redis Key：
   ```java
   String capacityKey = RedisKeys.COURSE_CAPACITY + courseId;  // elective:course:capacity:{id}
   String selectedKey = RedisKeys.COURSE_SELECTED + courseId;  // elective:course:selected:{id}
   ```
2. **确保缓存就绪**：若 `capacityKey` 不存在，需从数据库回源重建（建议加锁 + 双重检查）
3. **执行 Lua 脚本**：
   ```java
   Long result = stringRedisTemplate.execute(
           selectCourseScript,                       // RedisConfig 已注册的 Bean
           List.of(capacityKey, selectedKey),
           String.valueOf(studentId));
   ```

**Lua 返回值语义**（已定义在 `select_course.lua`）：

| 返回值 | 含义 | 对应处理 |
| --- | --- | --- |
| `0` | 预占成功 | 继续落库 |
| `1` | 已选过该课程 | 抛出 3003 |
| `2` | 余量不足 | 抛出 3002 |
| `3` | 缓存未初始化 | 抛出 3010 |

#### 规则 6：落库与回滚

```
预占成功
    ↓
写入选课记录（事务）
    ├─ 已有记录且 status=1  → 抛出 3003
    ├─ 已有记录且 status=0  → 复用记录，置 status=1、更新 selectTime、清空 dropTime
    └─ 无记录               → 新增记录，status=1、selectType=1
    ↓
成功 → courseMapper.increaseSelectedCount(courseId)
失败 → 回滚 Redis 预占（执行 drop_course.lua，归还余量 + 移除已选标记）
```

> ⚠️ **重要**：由于事务方法需通过代理调用，建议在 Service 中注入
> `ObjectProvider<CourseSelectionServiceImpl>` 获取自身代理，或将落库逻辑抽到独立 Bean，
> 避免 `this.persistSelection()` 自调用导致 `@Transactional` 失效。

#### 规则 7：退课

**前置校验**：

| 校验项 | 失败状态码 |
| --- | --- |
| 课程 `selectable != 1`（不允许退选） | 3009 |
| 未找到 `status = 1` 的选课记录 | 3004 |
| 该选课记录 `score != null`（已录入成绩） | 3009 |

**执行步骤**：

1. 更新选课记录：`status = 0`、`dropTime = now()`
2. 执行 `drop_course.lua` 归还 Redis 余量
3. `courseMapper.decreaseSelectedCount(courseId)`

> 注意：退课**不删除记录**，便于审计与重新选课复用。

#### 规则 8：缓存预热与同步

**`preloadCourseCache(semesterId)`**：

```java
// 1. 查询正常状态课程
List<Course> courses = courseMapper.selectList(...status = 1...);

// 2. 逐门课程重建缓存
for (Course course : courses) {
    // 查询真实已选学生
    List<CourseSelection> selections = list(...courseId, status = 1...);

    // 写入余量（String）
    int remaining = Math.max(maxCapacity - selections.size(), 0);
    stringRedisTemplate.opsForValue().set(capacityKey, String.valueOf(remaining),
            RedisKeys.DEFAULT_CACHE_MINUTES, TimeUnit.MINUTES);

    // 写入已选集合（Set）
    stringRedisTemplate.delete(selectedKey);
    stringRedisTemplate.opsForSet().add(selectedKey, studentIdArray);
}
```

**`syncSelectionCount()`**：

```java
// 对每门课程：比对数据库真实选课数 与 course.selected_count
// 不一致则：
//   1. courseMapper.syncSelectedCount(courseId)   // XML 中已实现该 SQL
//   2. 用真实值重算并覆盖 Redis 余量
```

### 3.2 涉及的业务规则

#### 规则 1：成绩计算

**总评成绩**：

```
总评 = 平时成绩 × 0.3 + 期末成绩 × 0.7
```

**单边缺失时的折算**：

| 平时 | 期末 | 总评 |
| --- | --- | --- |
| 有 | 有 | `usual × 0.3 + exam × 0.7` |
| 有 | 无 | `usual` |
| 无 | 有 | `exam` |
| 无 | 无 | `null` |

结果保留 1 位小数（`RoundingMode.HALF_UP`）。

**绩点换算（4.0 制分段）**：

| 总评区间 | 绩点 |
| --- | --- |
| ≥ 90 | 4.0 |
| 85-89 | 3.7 |
| 82-84 | 3.3 |
| 78-81 | 3.0 |
| 75-77 | 2.7 |
| 72-74 | 2.3 |
| 68-71 | 2.0 |
| 64-67 | 1.5 |
| 60-63 | 1.0 |
| < 60 | 0.0 |

**及格判定**：总评 ≥ 60（`Constants.PASS_SCORE`）记为及格，`is_pass = 1`。

#### 规则 2：成绩取值范围

- 平时成绩、期末成绩均须在 **0-100** 之间，否则抛出 `4003`；
- 允许为 `null`（表示暂未录入该项）。

#### 规则 3：状态流转

```
草稿(0) ──发布──▶ 已发布(1) ──归档──▶ 已归档(2)
   ▲                  │
   └──────撤回────────┘
```

| 状态 | 常量 | 能否修改成绩 |
| --- | --- | --- |
| 草稿 | `GRADE_STATUS_DRAFT = 0` | ✅ 可修改 |
| 已发布 | `GRADE_STATUS_PUBLISHED = 1` | ❌ 需先撤回（抛 4002） |
| 已归档 | `GRADE_STATUS_ARCHIVED = 2` | ❌ 需先撤回（抛 4002） |

#### 规则 4：权限校验

```java
// 管理员可直接操作；教师仅能操作自己授课的课程
private void checkTeacherPermission(Course course) {
    LoginUser loginUser = SecurityUtils.getLoginUser();
    if (loginUser.isAdmin()) {
        return;
    }
    if (!course.getTeacherId().equals(loginUser.getTeacherId())) {
        throw new BusinessException(ResultCode.NOT_COURSE_TEACHER);  // 4004
    }
}
```

#### 规则 5：录入逻辑（`inputGrades`）

**流程**：

1. 校验 `courseId` 非空，查询课程并做权限校验；
2. 遍历 `dto.getItems()`：
   - 校验成绩范围；
   - **定位选课记录**：优先用 `selectionId`，其次用 `studentId`（需 `course_id` + `status = 1`）；
   - 查询是否已有成绩记录（按 `selectionId` 唯一）：
     - 已发布/已归档 → 抛出 `4002`；
     - 新增时初始化 `studentId`/`courseId`/`semesterId`/`status = 0`；
   - 计算总评与绩点，设置 `inputTime`、`inputBy`；
   - 保存（`saveOrUpdate`）；
   - **同步**：将总评写回 `course_selection.score`，便于学生端快速展示。

#### 规则 6：发布逻辑（`publishGrades`）

**前置条件**：

- 权限校验通过；
- 课程存在草稿状态的成绩记录，否则抛「暂无可发布的成绩记录」；
- **所有草稿记录的总评成绩均不为 `null`**，否则抛出：
  ```
  还有 N 名学生未录入成绩，无法发布
  ```

**执行**：

1. 批量将草稿记录置为已发布，设置 `publishTime`；
2. **数据联动**：将对应选课记录 `status` 从 `1`（已选课）改为 `2`（已修完）。

> ⚠️ 注意：`course_selection` 状态改为 2 后，「我的选课」与课表查询的过滤条件
> 可能需要同步调整（课表查询当前只查 `status = 1`）。

#### 规则 7：撤回逻辑（`revokeGrades`）

- 权限校验；
- 将已发布记录改回草稿，清空 `publishTime`；
- 建议同时将选课记录状态从 `2` 改回 `1`（保持数据一致）。

#### 规则 8：成绩单统计（`getStudentGradeReport`）

**查询**：`CourseGradeMapper.selectStudentGrades(studentId, semesterId, publishedOnly = true)`
（仅统计已发布成绩）。

**统计项**：

| 指标 | 计算方式 |
| --- | --- |
| `totalCredit` | 所有课程学分求和 |
| `earnedCredit` | 仅及格课程的学分求和 |
| `averageScore` | 所有有总评成绩的课程的算术平均，保留 2 位小数 |
| `averageGradePoint` | `Σ(绩点 × 学分) / Σ(学分)`，保留 2 位小数 |

## 5. 实现顺序建议

```
阶段一：选课基础查询（快速见效）
  ├─ pageAvailableCourses      查询课程 + 补充 Redis 余量 + selected 标记
  ├─ pageMySelections          直接调用 Mapper
  └─ pageCourseStudents        直接调用 Mapper
        ↓
阶段二：时间冲突检测
  └─ checkConflict             实现四维判定（参考测试类）
        ↓
阶段三：选课与退课（核心）
  ├─ 缓存回源逻辑               ensureCacheReady / refreshCourseCache
  ├─ selectCourse              Lua 预占 + 落库 + 回滚
  └─ dropCourse                状态更新 + Lua 归还
        ↓
阶段四：缓存运维
  ├─ preloadCourseCache        批量重建缓存
  └─ syncSelectionCount        一致性校正（完成后启用定时任务）
        ↓
阶段五：成绩模块
  ├─ listCourseGradeSheet      录入单查询
  ├─ pageGrades                分页查询
  ├─ inputGrades               录入 + 计算 + 同步
  ├─ publishGrades / revokeGrades
  └─ getStudentGradeReport     成绩单统计
```

## 6. 验收清单

### 6.1 选课模块

- [ ] 可选课程列表能正确显示 Redis 实时余量
- [ ] 已选课程在学生视角正确标记 `selected = true`
- [ ] 并发选课（如 100 并发抢 50 容量）后，成功数恰为 50，无超选
- [ ] 重复选课被拒绝，返回 3003
- [ ] 时间冲突（同天、节次重叠、周次重叠、周类型兼容）被拒绝，返回 3005
- [ ] 单双周不冲突的场景能正常选课
- [ ] 超出学分上限被拒绝，返回 3008
- [ ] 选课关闭时（Redis 开关 off）被拒绝，返回 3007
- [ ] 落库失败时 Redis 余量正确归还（可模拟异常验证）
- [ ] 退课后余量正确 +1，选课记录状态变为 0
- [ ] 已录入成绩的课程无法退课
- [ ] 缓存预热后 Redis Key 数量与课程数一致
- [ ] 手工制造数据偏差后，同步接口能校正

### 6.2 成绩模块

- [ ] 总评成绩计算正确（平时 30% + 期末 70%）
- [ ] 单边成绩缺失时按规则折算
- [ ] 绩点换算与分段表一致
- [ ] 成绩超出 0-100 被拒绝，返回 4003
- [ ] 已发布成绩无法直接修改，返回 4002
- [ ] 存在未录入成绩的学生时无法发布
- [ ] 发布后学生能查询到成绩，选课记录状态变为 2（已修完）
- [ ] 撤回后学生无法查询，可继续修改
- [ ] 教师只能操作自己课程的成绩，越权返回 4004
- [ ] 成绩单统计（总学分、已获学分、平均分、平均绩点）计算正确
- [ ] 成绩分布图表数据正常（需同时恢复 `CourseServiceImpl` 中的 `scoreDistribution`）

### 6.3 前端联调

- [ ] 选课成功/失败的提示信息对用户友好
- [ ] 时间冲突时能展示具体冲突课程与时间
- [ ] 成绩录入支持批量填充与实时总评预览
