# 架构设计文档

> 本文档描述高校选修课管理系统的整体架构、模块划分、关键技术决策与扩展方向。

## 1. 设计目标

| 目标 | 说明 |
| --- | --- |
| **高并发选课安全** | 选课高峰期不超选、不重复选课，余量数据准确 |
| **业务完整性** | 覆盖选课、排课、成绩、公告、教务统计全流程 |
| **分层清晰** | 接口层、业务层、持久层职责单一，便于维护与测试 |
| **可部署性** | 支持本地开发与容器化一键部署 |
| **可扩展性** | 模块边界清晰，便于新增角色或业务能力 |

## 2. 整体架构

系统采用前后端分离架构，分为四层：

```
┌─────────────────────────────────────────────────────────────┐
│  接入层  Web 浏览器 / 微信小程序 / 第三方对接                    │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP / JSON（JWT 认证）
┌──────────────────────────▼──────────────────────────────────┐
│  表现层  Vue 3 SPA（Nginx 托管静态资源 + 反向代理 /api）        │
│          微信小程序（原生，直连后端 /api）                       │
└──────────────────────────┬──────────────────────────────────┘
                           │ RESTful API
┌──────────────────────────▼──────────────────────────────────┐
│  应用层  Spring Boot 3                                        │
│  ┌──────────┬──────────┬──────────┬──────────┬────────────┐ │
│  │Controller│ Service  │ Mapper   │ Security │ Aspect     │ │
│  └──────────┴──────────┴──────────┴──────────┴────────────┘ │
└─────────┬──────────────────────────────┬────────────────────┘
          │ JDBC                         │ Redis Protocol
┌─────────▼─────────┐          ┌─────────▼─────────┐
│   MySQL 8.0       │          │    Redis 7        │
│   业务持久化       │          │ 并发控制 / 缓存    │
└───────────────────┘          └───────────────────┘
```

## 4. 安全设计

### 4.1 认证流程

```
① 客户端 POST /auth/login 提交账号密码
        ↓
② 校验失败次数（Redis 计数，5 次锁定 15 分钟）
        ↓
③ PasswordEncoder.matches 校验密码（bcrypt / {noop}）
        ↓
④ 校验账号状态（是否禁用）
        ↓
⑤ JwtTokenProvider.generateToken 签发令牌
        ↓
⑥ 令牌写入 Redis 白名单（elective:auth:token:{userId}）
        ↓
⑦ 缓存学生/教师扩展 ID（供过滤器还原上下文）
        ↓
⑧ 返回 token + 用户基础信息
```

### 4.2 请求鉴权

`JwtAuthenticationFilter` 位于 `UsernamePasswordAuthenticationFilter` 之前：

1. 从 `Authorization` 请求头提取令牌（支持 `Bearer ` 前缀）；
2. 验签并解析 claims，失败则匿名放行（由 `RestAuthenticationEntryPoint` 统一返回 401）；
3. 校验令牌是否仍在 Redis 白名单（支持服务端主动注销）；
4. 从 Redis Hash 恢复 `studentId` / `teacherId` / `deptId`；
5. 写入 `SecurityContext`；
6. 剩余有效期低于阈值时自动续期（滑动过期）。

### 4.3 授权模型

- 基于角色的访问控制（RBAC），角色为 `STUDENT` / `TEACHER` / `ADMIN`；
- URL 级别：`SecurityConfig` 中通过 `requestMatchers` 声明前缀权限；
- 方法级别：`@EnableMethodSecurity` + `@PreAuthorize`（预留）；
- 数据级别：Service 内校验归属（如教师只能录入自己的课程成绩）。

### 4.4 安全策略汇总

| 风险 | 措施 |
| --- | --- |
| 密码泄露 | bcrypt 加盐哈希，实体密码字段 `@JsonIgnore` |
| 暴力破解 | 登录失败计数与临时锁定 |
| 令牌盗用 | Redis 白名单 + 有效期 + 修改密码强制失效 |
| 越权访问 | URL + 方法 + 数据三层校验 |
| 参数注入 | MyBatis-Plus 参数绑定，XML 使用 `#{}` |
| 全表误更新 | `BlockAttackInnerInterceptor` 拦截 |
| 敏感信息外泄 | 生产环境关闭接口文档、异常信息脱敏 |

## 5. 核心业务设计

### 5.1 选课并发控制

详见 [README 选课并发方案](../README.md#选课并发方案)。核心要点：

- **原子性**：Lua 脚本在 Redis 单线程中执行，四步合一；
- **幂等性**：Set 结构天然去重，配合数据库唯一索引双重保障；
- **可用性**：缓存缺失时自动回源重建（`synchronized` + 双重检查）；
- **一致性**：定时任务校正 DB 计数与 Redis 余量；
- **可回滚**：落库失败时执行退课脚本归还预占。

### 5.2 时间冲突检测

四维判定：星期相同、节次区间重叠、周次区间重叠、周类型兼容。

应用在两个位置：

| 时机 | 方法 | 目的 |
| --- | --- | --- |
| 选课预检 | `CourseSelectionService.checkConflict` | 提前告知用户冲突详情，避免无效请求进入 Redis |
| 排课校验 | `CourseService.validateScheduleConflict` | 防止教师时间冲突、教室占用冲突 |

### 5.3 成绩管理

```
教师录入（草稿）→ 教师发布 → 学生可查
       ↑                │
       └──── 撤回发布 ←──┘
```

- 总评计算：`usual × 0.3 + exam × 0.7`（单边缺失时按已有成绩折算）；
- 绩点换算：4.0 制分段映射；
- 发布约束：存在未录入成绩的学生时禁止发布；
- 数据联动：发布后同步将选课记录状态置为「已修完」，并回写成绩到选课表。

### 5.4 教学评价

```
学生提交（已修完课程）→ 状态「已提交」→ 管理员审核公开 → 状态「已公开」（教师可见）
                              ↑                    │
                       修改后回退为已提交 ──────────┤
                                                   ▼
                                            管理员可隐藏（已隐藏）
```

- **参评资格**：仅限 `course_selection.status = 2`（已修完）的课程；
- **一课一评**：以 `selection_id` 唯一索引约束，重修课程各自独立评价；
- **匿名保护**：`anonymous = 1` 时，身份过滤集中在 VO 层完成，
  教师端与公开列表不下发 `studentId` / `stuNo`；
- **状态回退**：学生修改评价后状态回到「已提交」，需管理员重新公开，
  防止先获好评、后改差评绕过审核；
- **物理删除**：撤回与删除均为物理删除，否则 `selection_id` 唯一键会持续占用，
  学生无法重新提交（该表因此也是全库唯一不含 `deleted` 字段的业务表）；
- **统计口径**：平均分仅统计非隐藏评价；参评率分母取「已修完」人数而非「已选」人数。

### 5.5 缓存策略

| 缓存内容 | Key | 过期时间 | 更新时机 |
| --- | --- | --- | --- |
| 课程余量 | `elective:course:capacity:{id}` | 30 分钟 | 选课/退课/预热/同步 |
| 已选集合 | `elective:course:selected:{id}` | 30 分钟 | 选课/退课/预热 |
| 令牌白名单 | `elective:auth:token:{uid}` | 令牌有效期 | 登录/续期/注销 |
| 用户扩展信息 | `elective:auth:user:{uid}` | 令牌有效期 | 登录 |
| 选课开关 | `elective:selection:switch` | 永久 | 管理员切换 |

## 6. 前端架构

### 6.1 目录组织

```
src/
├── api/          按业务模块拆分的接口封装
├── layout/       主布局（侧边栏 + 顶栏 + 内容区）
├── router/       路由表 + 全局守卫
├── store/        Pinia store（user / app）
├── styles/       全局样式 + SCSS 变量
├── utils/        request 封装 / 字典 / 令牌存储
└── views/        页面（按角色分目录）
```

### 6.2 路由权限

`router/guard.js` 实现两级校验：

1. **登录校验**：无令牌且不在白名单 → 跳转登录页并携带 `redirect`；
2. **角色校验**：解析路由匹配链上最靠下的 `meta.roles`，与当前用户角色比对，不匹配跳转 403。

菜单渲染由 `SidebarMenu.vue` 依据 `constantRoutes` 与用户角色动态过滤。

### 6.3 请求封装

`utils/request.js` 统一处理：

- 请求拦截：自动附加 `Authorization` 头、启动 NProgress；
- 响应拦截：识别 `code !== 200` 的业务错误、统一提示、401 自动登出并弹窗引导重登录；
- 并发保护：`isReloginPrompted` 标志避免多个并发请求重复弹出登录失效提示。

### 6.4 小程序架构

`miniprogram/` 为**原生微信小程序**（WXML / WXSS / JS），无构建工具链，
面向学生提供教学评价、课表与成绩查询。

```
miniprogram/
├── app.js / app.json / app.wxss   入口、页面注册、全局样式（CSS 变量对齐 Element Plus）
├── config/index.js                baseUrl、缓存键名、超时
├── utils/
│   ├── request.js                 请求封装（与 Web 端同一套语义）
│   └── dict.js                    字典与工具方法（与 Web 端保持一致）
├── api/                           接口封装（auth / common / review / student）
└── pages/                         8 个页面
```

**与 Web 端的设计对齐**（两侧必须保持一致，切勿单侧修改）：

| 约定 | 说明 |
| --- | --- |
| 响应判定 | `code === 200` 为成功，业务数据在 `data` 字段 |
| 登录失效 | 401 与业务码 `2003` 均视为失效，清理缓存后跳登录页 |
| 并发保护 | 用 `isHandlingUnauthorized` 标志位防止并发请求重复跳转（对应 Web 端的 `isReloginPrompted`） |
| 字典同步 | 状态文案与颜色在 `utils/dict.js` 双份维护，改动需两侧同步 |

> 小程序**复用后端既有接口，无专用接口**。微信一键登录、订阅消息等
> 需后端新增能力的场景，记录在 [待实现功能 4.7.1 节](./待实现功能.md#471-需要后端支持的增强功能待实现)。

## 7. 技术决策记录

| 决策 | 备选方案 | 选择理由 |
| --- | --- | --- |
| 选课并发控制 | 数据库悲观锁 / 分布式锁（Redisson） | Lua 脚本性能最优，无锁等待，天然防超选 |
| 认证方案 | Session / JWT | JWT 无状态，配合 Redis 白名单兼顾安全与水平扩展 |
| ORM | JPA / MyBatis-Plus | MyBatis-Plus 对复杂 SQL 与分页支持更灵活 |
| 逻辑删除 | 物理删除 | 保留历史数据，满足教务审计需求 |
| 前端 UI | Ant Design Vue / Element Plus | Element Plus 生态成熟、组件完备 |
| 令牌存储 | 仅 localStorage | sessionStorage 优先，降低 XSS 长期风险 |
| 表结构初始化 | Flyway / Spring SQL 初始化 | 自定义组件实现，无需额外依赖与脚本副本，且能规避 schema.sql 中 DROP 语句的风险 |

## 8. 数据库表结构自动初始化

开发环境下，应用启动时自动创建缺失的数据表，降低环境搭建成本。

### 8.1 实现方式

`config/DatabaseInitializer.java` 实现，核心流程：

```
应用启动（ApplicationReadyEvent）
        ↓
读取 classpath:db/schema.sql
        ↓
过滤库级与破坏性语句（CREATE DATABASE / USE / DROP TABLE / SET）
        ↓
CREATE TABLE → CREATE TABLE IF NOT EXISTS（幂等改写）
        ↓
查询 information_schema 比对表是否已存在
        ↓
仅执行缺失表的建表语句
```

### 8.2 生效范围

| 环境 | 是否启用 | 控制方式 |
| --- | --- | --- |
| 非 prod（dev / test） | ✅ 默认启用 | `@Profile("!prod")` + `elective.database.auto-init` |
| prod | ❌ 强制禁用 | 类被 profile 排除，配置项亦设为 false |

### 8.3 安全保障

| 风险 | 应对措施 |
| --- | --- |
| 误删已有数据 | 过滤脚本中的 `DROP TABLE`，已存在的表不执行任何 DDL |
| 重复执行产生副作用 | 所有语句改写为 `IF NOT EXISTS`，天然幂等 |
| 并发启动重复建表 | 捕获 MySQL 1050 错误（表已存在）视为成功 |
| 初始化失败阻断启动 | 异常仅记日志，不影响应用启动 |
| 生产环境误操作 | prod 环境整体禁用该组件 |

### 8.4 设计取舍

选择自定义组件而非 Flyway / Spring `sql.init` 的原因：

- **Flyway**：功能完备，但需引入依赖、调整脚本命名规范，对当前项目偏重；
- **Spring `sql.init`**：官方机制简单，但需维护一份独立的建表脚本副本，且 `schema.sql` 中的
  `DROP TABLE` 若不拆分，每次启动都会清空数据；
- **自定义组件**：直接复用现有 `schema.sql` 作为唯一事实来源，无需维护副本，
  且能精确过滤危险语句，改动最小、风险可控。

> 若项目后续进入长期演进阶段（需要版本化迁移与回滚能力），可平滑切换至 Flyway。

## 9. 扩展方向

- **选课排队**：引入消息队列削峰，将落库异步化；
- **分布式部署**：接入 Nacos 注册中心与 Spring Cloud Gateway；
- **缓存高可用**：Redis Sentinel / Cluster；
- **数据导出**：基于 EasyExcel 导出成绩单与选课报表；
- **消息通知**：选课成功、成绩发布接入邮件 / 站内信；
- **可观测性**：接入 Prometheus + Grafana，暴露 JVM 与业务指标；
- **小程序增强**：微信一键登录（需 `openid` 绑定）、订阅消息推送、评价趋势图表；
- **评价可视化**：各维度雷达图、跨学期评分趋势对比。
